# Audit event schema

This document defines the JSONL audit records written by `audit.py`. Each
non-empty line in `logs/audit.jsonl` is one UTF-8 JSON object. The logger
appends records; it does not update earlier events. Every completed HTTP
request produces a `request` event. A route may also produce a domain event
such as `decision`, `appeal`, or `rejected`; events from the same HTTP request
share a request ID.

## Shared conventions

- Every event has a `timestamp` string in ISO 8601 UTC format.
- `creator_id` and `content_id` are identifiers supplied or generated by the
  application; they are not proof of a caller's identity.
- Numeric scores are JSON numbers or `null` when unavailable.
- `request_id` is generated by the server for each HTTP request and is returned
  to the caller in the `X-Request-ID` response header. Do not treat an
  incoming caller-supplied ID as trusted.
- Additional fields are permitted for operational context, so readers should
  ignore fields they do not recognize.

## Local log safeguards

- Audit files are stored under `logs/`, with directory permissions `0700` and
  active file permissions `0600` on POSIX systems.
- The active JSONL file rotates at 5 MiB. Three numbered backups are retained;
  older records are discarded when the backup set fills. Rotation is size-based,
  not time-based.
- `/log` accepts loopback clients only and returns at most 100 records. A
  requested limit above 100 is capped; invalid, zero, or negative limits return
  `400`.
- Decision text (`submitted_text`) and appeal reasoning may contain sensitive
  information. Each is capped at 4,000 characters, with a truncation flag.
  Request-level events do not include request bodies or headers.

## HTTP request

Written once by the Flask `after_request` hook for every completed response,
including not-found responses and server errors handled by Flask.

| Field | Type | Required | Meaning |
|---|---|---:|---|
| `timestamp` | string | Yes | UTC event time |
| `event` | string | Yes | `request` |
| `request_id` | string | Yes | Server-generated correlation ID |
| `method` | string | Yes | HTTP method |
| `path` | string | Yes | Requested URL path, without query string |
| `endpoint` | string or null | Yes | Flask endpoint name; null when no route matched |
| `status_code` | integer | Yes | HTTP response status code |
| `outcome` | string | Yes | `success` for status below 400, `rejected` for 400-499, `error` for 500+ |
| `duration_ms` | number | Yes | Request processing duration in milliseconds |

Request events intentionally do not record request bodies, cookies, headers, or
client IP addresses.

## Decision

Written by `log_decision`.

| Field | Type | Required | Meaning |
|---|---|---:|---|
| `timestamp` | string | Yes | UTC event time |
| `event` | string | Yes | `decision` |
| `request_id` | string | No | ID of the HTTP request that generated the decision |
| `content_id` | string | Yes | ID for the submitted content |
| `creator_id` | string | Yes | Creator identifier |
| `guess` | string or null | Yes | Detector guess |
| `model_score` | number or null | Yes | Model signal |
| `style_score` | number or null | Yes | Style signal |
| `combined_score` | number or null | Yes | Combined score |
| `label` | string or null | Yes | Final label |
| `status` | string | Yes | Normally `decided` |
| `submitted_text` | string | No | Submitted text when explicitly provided to the logger; capped at 4,000 characters |
| `submitted_text_truncated` | boolean | No | Whether the submitted text exceeded the cap |

## Appeal

Written by `log_appeal`.

| Field | Type | Required | Meaning |
|---|---|---:|---|
| `timestamp` | string | Yes | UTC event time |
| `request_id` | string | No | ID of the HTTP request that submitted the appeal |
| `content_id` | string | Yes | ID of the appealed content |
| `creator_id` | string | Yes | Creator identifier |
| `event` | string | Yes | `appeal` |
| `status` | string | Yes | `under_review` |
| `reasoning` | string | Yes | Appeal explanation; may contain sensitive user text, capped at 4,000 characters |
| `reasoning_truncated` | boolean | Yes | Whether reasoning exceeded the cap |

## Rejection

Written by `log_rejection`.

| Field | Type | Required | Meaning |
|---|---|---:|---|
| `timestamp` | string | Yes | UTC event time |
| `request_id` | string | No | ID of the HTTP request that was rejected |
| `creator_id` | string | Yes | Creator identifier, or `unknown` |
| `event` | string | Yes | `rejected` |
| `status` | string | Yes | `rejected` |
| `reason` | string | Yes | Rejection reason code |

Rejections may include contextual fields such as `limit`. `content_id` is not
required because rejected requests may not have reached the point where a
content ID was created.

## Compatibility and next schema revision

The writer permits additional fields and the reader skips malformed lines.
Tests in `test_audit.py` capture the event contracts, content caps, file
permissions, rotation, and response-outcome classification. Never record
credentials, cookies, or authorization headers.

## Rate limiting

When enabled, `POST /submit` is limited to 10 requests per minute and 200 per
day per client address. The configured in-memory counter resets on process
restart and is not shared across instances. Clients behind the same NAT or
loopback address share a quota. `creator_id` is not used as a rate-limit key
because it is caller-controlled.
